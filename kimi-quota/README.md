# Kimi 额度（kimi-quota）

使用 Kimi 模型时，长任务中途默认每 10 分钟检查并播报一次用量；任务结束时再主动刷新，显示 5 小时、月度已用比例和各自的重置时间。也可以用 `/kimi-quota` 手动查询。

使用其他模型时，不显示状态行，也不发起额度查询请求。

## 状态行示例

`Kimi` 已用 · 5h 🟢 **2%** · 月 🟢 **2.1%** · 重置 5h 16:29 · 月 11/01 08:00

百分比均为已用比例，时间为本地时间。使用 `Kimi` 小标签和加粗百分比，与正文空一行，不使用引用或分隔线。

5 小时和月度分别判断：已用比例超过 80% 显示 🔴，80% 及以下显示 🟢。颜色按实际比例判断；刚超过阈值、四舍五入会显示成 80% 时，显示 `>80%`。缺失数据显示 `—`，不加圆点。

月度优先总额度，接口未提供总额度池时使用 Code 月额度；缺失的重置时间显示 `—`。

## 工作方式

- 开始时只判断模型、记录本轮时间并提供展示规则，不查询额度，也不要求模型复用历史数值。
- 工具执行成功或失败后，检查距上次播报是否已满 10 分钟；到了才查询接口并要求模型展示一行，然后继续当前任务。各轮次、各会话独立计时，并发事件只触发一次。
- 后台任务通知等内部续跑即使跳过用户提交事件，也会建立独立轮次；首个工具事件开始计时，结束时照常刷新。新用户消息会使已知旧轮次失效，避免迟到事件覆盖当前任务。
- 这不是固定时刻的后台推送。单个命令长时间不返回时，会等到下一个工具结束节点；实际播报仍依赖模型执行提示。
- 结束时主动查询一次，使用这次返回的值。若末尾缺少或仍是旧值，只请求模型补充一行，不重做正文或任务；结束续跑与重复事件不会再次查询。
- 中途查询失败后安静跳过，至少隔 60 秒再尝试；结束查询不受这个退避限制，失败后不补发历史额度，也不在本轮反复重试。
- 不再使用开头的额度快照或旧版额度缓存。会话状态只保存模型、计时和处理标记，不保存可复用的额度或密钥；旧缓存文件无需手动删除。
- 额度来自 `https://api.kimi.com/coding/v1/usages`，查询使用只读 GET 请求。每次实际查询都读取当前凭据，优先使用环境变量 `KIMI_API_KEY`，否则使用 ZCode 已配置的 Kimi 供应商密钥。

如需调整中途播报间隔，可向 Hook 进程设置 `KIMI_QUOTA_PROGRESS_INTERVAL`（秒），例如 `300` 表示 5 分钟。有效范围为 60–86400 秒，未设置或无效时使用默认的 600 秒。

更新插件后，请新建会话验证；已启动的会话使用原有的 hook 配置。同一会话切换模型时，后续事件会重新读取数据库；由于 ZCode 并非每轮都传入模型信息，提问开始时的判断仍受同步时序影响，新建会话可使用明确的模型输入。

## 本地回归

运行 `python3 -m unittest discover -s kimi-quota/tests -v`（在仓库根目录执行）。测试使用临时目录、模拟时钟、接口和密钥，覆盖长任务与并发事件，不读取真实密钥或请求网络。
