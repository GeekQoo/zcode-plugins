# Kimi 额度（kimi-quota）

使用 Kimi 模型时，回复末尾会显示 5 小时、月度已用比例和各自的重置时间。也可以用 `/kimi-quota` 手动查询。

使用其他模型时，不显示状态行，也不发起额度查询请求。

## 状态行示例

> Kimi 已用 · 5h **2%** · 月 **2.1%**｜重置 5h 16:29 · 月 11/01 08:00

百分比均为已用比例，时间为本地时间。引用样式跟随 ZCode 主题，百分比加粗。月度优先总额度，接口未提供总额度池时使用 Code 月额度；缺失数据或重置时间显示 `—`。

## 工作方式

- 会话开始时优先读取 ZCode 传入的当前模型，并按会话保存；后续以本地会话记录补充判断，首条消息即可注入额度。
- 每轮用户消息都会向模型提供状态行。接口数据按凭据和地址隔离缓存 5 分钟，缓存期间仍可展示，各会话互不抑制。
- 回复结束时检查末尾是否有本轮状态行；缺少时请求模型补充一次，避免反复续跑。手动查询已展示的新数据不会被旧快照替换。自动展示依赖模型执行这些提示。
- 缓存过期且查询失败时，本轮不展示过期额度。凭据指纹不可用时直接查询，不复用缓存。
- 手动查询另存本地回执，最多保留一天内的 32 条，只用于核对回复末尾，不作为自动展示的数据来源。
- 额度数据来自 `https://api.kimi.com/coding/v1/usages`，与官方 CLI 同源。查询使用只读 GET 请求，结果缓存 5 分钟。
- 优先从环境变量 `KIMI_API_KEY` 读取 API Key；未设置时，使用 ZCode 中已配置的 Kimi 供应商密钥。

更新插件后，请新建会话验证；已启动的会话使用原有的 hook 配置。同一会话切换模型时，后续事件会重新读取数据库；由于 ZCode 并非每轮都传入模型信息，提问开始时的判断仍受同步时序影响，新建会话可使用明确的模型输入。

## 本地回归

运行 `python3 -m unittest discover -s kimi-quota/tests -v`（在仓库根目录执行）。测试使用临时目录、模拟接口和测试密钥，不读取真实密钥或请求网络。
