# DeepSeek 余额查询（deepseek-balance）

显示 DeepSeek 官方账户的总余额、充值余额和未过期赠金，余额较低时在状态行中提醒。长任务默认每 10 分钟在工具结束节点检查一次，任务结束时再刷新；支持 `/deepseek-balance` 手动查询。

独立安装和运行，不依赖 Kimi 额度查询插件。两者的模型门控、状态目录和配置变量相互独立。

## 展示示例

正常余额：

`DeepSeek` 余额 🟢 **¥110.00** · 充值 ¥100.00 · 赠金 ¥10.00

低余额：

`DeepSeek` 余额 🔴 **¥9.25**（低余额 ≤ ¥10.00） · 充值 ¥9.25 · 赠金 ¥0.00

- 人民币默认阈值为 ¥10，美元为 US$2；达到或低于阈值显示红色和“低余额”，高于阈值显示绿色。
- 接口返回多个币种时分别展示、分别判断，不换汇、不相加。美元用 `US$` 标识。
- 接口明确返回 `is_available: false` 时显示红色并提示“余额不足，无法调用”。
- 金额至少显示两位小数，有更多有效小数位时保留，避免阈值附近四舍五入造成误解。充值或赠金字段缺失时显示 `—`；总余额或关键字段无效时跳过自动播报。
- 这是账户共享余额，不是本会话花费或某个 API Key 独享的余额；不提供月度百分比、重置时间或根据余额差估算任务成本。

## 凭据与模型识别

查询固定使用 [DeepSeek 官方余额接口](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)：`GET https://api.deepseek.com/user/balance`。

1. 优先使用 Hook 进程中的 `DEEPSEEK_API_KEY`。
2. 未设置时，只读 ZCode 的 `~/.zcode/v2/provider_config.json`，从当前会话模型所属供应商的 `config.access.apiKey` 读取密钥。

自动播报按会话模型的 `供应商ID/模型ID` 识别。默认供应商 ID 为 `deepseek`；自定义供应商只要在配置中的 `config.api.baseUrl` 为官方地址，也能自动识别。支持官方根地址及 `/v1`、`/anthropic`、`/beta`，均允许尾斜杠；余额查询始终使用根地址下的 `/user/balance`。

如果 ZCode 使用其他供应商 ID 且没有显式保存 base URL，可设置 `DEEPSEEK_BALANCE_PROVIDER_ID`。显式配置为第三方地址的供应商不会因这个变量而被放行。其他供应商的模型即使命名包含 DeepSeek，也不会自动触发。

手动查询使用环境变量密钥，或指定供应商 ID；均未设置时选择配置中唯一的官方供应商。多个官方供应商同时存在时不自动选账号，需要指定 ID 或密钥。设置环境变量密钥意味着明确使用该密钥所属账户，优先级高于 ZCode 中的密钥。

密钥只发往固定官方 HTTPS 地址，经标准输入交给 curl，不进入进程参数和日志。不跟随重定向，禁用用户 curlrc，不提供接口地址覆盖选项。接口响应不会落盘。

## 配置

以下环境变量需传给 ZCode/Hook 进程；只在另一个终端中 `export`，通常不会影响已经启动的桌面应用。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 从 ZCode 读取 | 显式指定官方 API Key |
| `DEEPSEEK_BALANCE_PROVIDER_ID` | `deepseek`（自动模式无 base URL 时） | 自定义供应商标识或手动查询账号选择 |
| `DEEPSEEK_BALANCE_LOW_CNY` | `10` | 人民币低余额阈值 |
| `DEEPSEEK_BALANCE_LOW_USD` | `2` | 美元低余额阈值 |
| `DEEPSEEK_BALANCE_PROGRESS_INTERVAL` | `600` | 中途检查间隔，秒，范围 60–86400 |

阈值接受非负十进制数，最多 12 位整数和 8 位小数。负数、非数字或超出格式限制时回退到相应币种的默认值。提醒在每次成功播报时判断，不是独立的后台通知。

本地手动查询示例（已在 ZCode 配置官方凭据时）：

```bash
DEEPSEEK_BALANCE_LOW_CNY=20 bash deepseek-balance/hooks/deepseek_balance.sh query
```

## 工作方式与限制

- 开始时只判断模型、初始化本轮计时并注入展示规则，不查询余额。
- 工具成功或失败后，距上次成功播报达到设定间隔才查询。并发事件去重；失败后至少隔 60 秒重试，避免密集请求。
- 等待子智能体或长命令期间不会准点推送，需等下一个主会话工具结束节点。内部续跑有独立计时，新用户消息会使已知旧轮次失效。
- 结束时主动查询一次；若末尾已是相同状态行，直接结束。否则请求模型完整复现已完成的正文，再在末尾附上最新余额，禁止重新调用工具或执行任务。
- 结束补齐最多请求一次；重复 Stop、补齐续跑不再次查询。查询失败安静跳过，不复用历史余额。手动查询失败会显示简短错误。
- ZCode 的 Stop Hook 无法直接追加到原消息，最终正文保留仍依赖模型遵守提示。补齐会增加输出用量和耗时，余额取自补齐前的查询时刻，不包含这次补齐的后续消耗。
- 余额不足到无法继续调用模型时，Hook 即使查到余额，也可能无法让模型完成最后的播报。
- 状态保存在 `~/.cache/deepseek-balance/`，仅记录模型、计时、处理标记和调用日志，不保存余额或密钥。更新或安装后请新建会话验证。
